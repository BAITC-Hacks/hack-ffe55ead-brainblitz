# Backend: запуск, проверка и подключение интерфейса

Реализованный этап ветки `nurdaulet`: математическая модель и HTTP API по актуальным [спецификации](spec.md), [контракту](api-contract.md) и [архитектуре](architecture.md) из `main`. Версии: контракт `2.0`, данные `city-v1`, правила `five-directions-v1`.

Работают `GET /api/config`, `POST /api/simulate` и `GET /health`. Существующий frontend принят из актуальной `main` (`cc008d75`, слияние PR #2) и обслуживается через `/` и `/static/*`; содержимое `static/` не изменялось. AI и `POST /api/analyze` не реализованы; отсутствующий маршрут возвращает 404. Числовой backend не требует AI-ключа, сети для расчёта, базы данных или авторизации.

## Запуск и зависимости

Проверенная среда: Windows, CPython **3.12.14**. Выполните из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

`requirements.txt` фиксирует полный набор runtime- и test-зависимостей с версиями. Установка воспроизведена в отдельном чистом окружении `.venv-verify`; `pip check` прошёл. Активация окружения не нужна: команды явно используют его интерпретатор.

Адреса после старта:

- `http://127.0.0.1:8000/` — интерфейс, подключённый к настоящему backend; открывайте без `?demo=1`.
- `http://127.0.0.1:8000/health` — ровно `{"status":"ok"}`.
- `http://127.0.0.1:8000/api/config` — полный каталог и исходный Score.
- `http://127.0.0.1:8000/docs` — интерактивная документация запросов.

## Структура реализации

| Файл | Ответственность |
| --- | --- |
| `app/models.py` | Строгие запросы и ответы Pydantic, запрет лишних полей и нечисловых значений |
| `app/validator.py` | Единый порядок проверок, ошибки 422 и канонический порядок решений |
| `app/simulation.py` | Чистые функции базовой оценки, эффектов и симуляции |
| `app/main.py` | Загрузка и проверка данных при старте, неизменяемая конфигурация, HTTP и ошибки |
| `data/districts.json` | Все пять районов, десять показателей, веса и доли населения |
| `data/measures.json` | Полные M1–M14, бюджет, лаги, конфликты, синергии и правила |

Конфигурация загружается один раз при старте и рекурсивно замораживается. Каждый расчёт создаёт свои показатели; повторный запрос не накапливает эффекты предыдущего. Ошибка целостности датасета останавливает запуск.

## Запрос и результат

`POST /api/simulate` принимает только объект с `selections`. Пример B:

```json
{
  "selections": [
    {"measure_id": "M1", "district_id": "esil"},
    {"measure_id": "M4", "district_id": "saryarka"},
    {"measure_id": "M7", "district_id": "nura"},
    {"measure_id": "M10", "district_id": "esil"},
    {"measure_id": "M12", "district_id": null}
  ]
}
```

Для A замените только район M7 на `esil`. У городской меры район должен отсутствовать или быть `null`; строка `"city"` не допускается. ID регистрозависимы. Цены, категории, эффекты и бюджет определяет сервер; передавать их в запросе нельзя. Bare array, `decisions`, неизвестные поля и автоматическое преобразование чисел в строковые ID не поддерживаются.

Проверка B из PowerShell:

```powershell
$scenario = Get-Content -Raw examples/scenario_b.json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/simulate -ContentType 'application/json' -Body $scenario
```

HTTP 200 содержит `SimulationResult` непосредственно, без внешней обёртки: версии, нормализованные `selections`, исходный и итоговый Score, дельту, стоимость и остаток, `score_breakdown`, пять районов до/после, критические пары, применённые эффекты и синергии. Полная структура и пример находятся в [API-контракте](api-contract.md#5-post-apisimulate). `explanation_source="rules"` означает детерминированную строку; это не AI-разбор.

| Сценарий | Стоимость | Score | Критических пар |
| --- | --- | --- | --- |
| База без мер — только конфигурация и внутренний расчёт | 0 | 52.55768 | 2 |
| A: M1 esil, M4 saryarka, M7 esil, M10 esil, M12 null | 83 | 53.8250475 | 2 |
| B: M1 esil, M4 saryarka, M7 nura, M10 esil, M12 null | 83 | 55.0703475 | 1 |

Пустой `selections` не запрашивает базу — это ошибка количества. Базовый Score берётся из `/api/config`.

## Валидация и расчёт

Проверки выполняются последовательно: структура/типы/лишние поля → ровно пять решений → неизвестные ID мероприятий → повторы → районы и область действия → по одной мере каждой категории → несовместимости → бюджет не выше 100. Возвращается одна первая ошибка. Путь ошибки относится к входному порядку, а успешный результат сортирует меры по числовой части ID.

Ожидаемые ошибки имеют HTTP 422 и ровно такую структуру:

```json
{
  "detail": [
    {
      "code": "BUDGET_EXCEEDED",
      "message": "Стоимость решений 107 превышает бюджет 100 на 7 единиц.",
      "path": ["selections"],
      "context": {"budget": 100, "total_cost": 107, "over_by": 7}
    }
  ]
}
```

Score в ошибке отсутствует. Полный список кодов — в [разделе ошибок контракта](api-contract.md#7-ошибки-запросов). Неожиданная ошибка даёт HTTP 500 с безопасным `INTERNAL_ERROR`, без stack trace в ответе.

Модель последовательно суммирует эффекты с коэффициентом `(8 − lag) / 8`, фиксированные синергии, затем один раз ограничивает показатели диапазоном 0–100. Районные оценки используют веса датасета, средняя — доли населения. Формула: `Score = 0.7 × average + 0.3 × minimum − critical_count`. Критическая пара имеет значение строго меньше 40. Промежуточного округления и ограничения итогового Score диапазоном 0–100 нет.

## Подключение frontend

Существующие `static/index.html`, `static/styles.css` и `static/app.js` обслуживаются этим же сервером: `/` отдаёт HTML, `/static/*` — локальные ресурсы. Открывайте интерфейс через сервер без `?demo=1`, чтобы использовать реальные расчёты. Отдельный frontend-сервер, сборка и CORS для согласованной архитектуры не нужны.

Минимальный пример для браузера:

```javascript
const configResponse = await fetch('/api/config');
if (!configResponse.ok) throw new Error('Не удалось загрузить конфигурацию.');
const config = await configResponse.json();

async function simulate(selections) {
  const response = await fetch('/api/simulate', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ selections }),
  });
  const body = await response.json();
  if (!response.ok) {
    const issue = body.detail?.[0];
    return { ok: false, issue, message: issue?.message ?? 'Ошибка расчёта.' };
  }
  return { ok: true, result: body };
}
```

Стройте форму и предварительную стоимость из `config`, используйте `config.baseline_score` до первого расчёта. При успехе отображайте `result.final_score`, `remaining_budget`, `districts` и критические показатели. Форматируйте числа до двух знаков только в интерфейсе. Для реакции на ошибку используйте `issue.code`, для подсветки поля — `issue.path`; текст не нужно разбирать программно.

При дальнейшем развитии интерфейса обрабатывайте сетевую ошибку вокруг вызова `simulate` через `try/catch`, помечайте прежний результат устаревшим при изменении выбора и игнорируйте запоздалые ответы по номеру попытки. При 422 старый Score не должен показываться как результат ошибочного набора. Существующий frontend уже делает отдельный запрос `/api/analyze` после успешного расчёта; текущий ответ 404 показывает недоступность AI и сохраняет числа. Backend этого этапа намеренно не добавляет замену AI или фиктивный успешный разбор.

## Проверки и известное расхождение в документах

Проверено **131 тест**, включая FastAPI TestClient. Один `StarletteDeprecationWarning` сообщает, что использование `httpx` в TestClient устаревает в пользу `httpx2`; предупреждение не подавлено. Закреплённые версии совместно прошли тесты и проверку зависимостей.

Отдельно выполнена интеграционная проверка в headless Microsoft Edge с настоящим Uvicorn, **без mock-ответов и перехвата API**. `/`, `/static/app.js` и `/static/styles.css` вернули 200. Интерфейс показал A с 53,83 и B с 55,07 при стоимости 83, сохранил числа после ответа 404 от AI, а конфликт M4 nura + M7 nura показал реальную ошибку 422 без Score. Ошибок JavaScript не обнаружено. После получения актуального frontend повторный полный прогон сохранил результат 131 passed, одно предупреждение; `pip check` прошёл.

Покрыты база/A/B с абсолютным допуском `1e-8`, все районные изменения, бюджет 100 и 107, неверные ID/типы/количество/повторы/категории/районы, несовместимости и порядок проверок, лаги, три исходные синергии, городской охват, отрицательные эффекты, clip, граница 40, неизменность базы и независимость от перестановки решений. Две синергии одного направления проверяются на уровне математического ядра; HTTP-правило категорий не обходится. Проверяются схемы успешных ответов и точные ошибки 422, а также запуск с повреждённым датасетом.

В разделе 8 `docs/spec.md` есть арифметическая описка: M3 nura, M4 saryarka, M7 nura, M10 esil, M12 null стоят **95**, хотя пример назван проверкой 100. Корректный набор ровно на **100**: M3 nura, **M6 null**, M7 nura, M10 esil, M12 null. Для 107: M3 nura, M5 saryarka, M7 nura, M10 esil, M14 null. Тесты используют реальные стоимости каталога; исходные спецификация, контракт и архитектура этим этапом не изменяются.

В ограниченной среде повторный прогон также прошёл с отключением кэша pytest и новой временной папкой внутри workspace:

```powershell
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --basetemp=work/pytest-run-fresh
```

Для каждого такого запуска выбирайте **новую, ещё не существующую** папку `--basetemp`, поскольку pytest может очищать содержимое указанной временной папки. Для обычного запуска используйте основную команду `python -m pytest -q` через интерпретатор `.venv`.
